My Evidence (V1) — Dependability Strategy for Nafath (نفاذ):

I selected Nafath (the Saudi National Single Sign-On) as my real-world system and produced a full dependability strategy in Week-02-Dependability/evidence-1.md:

  • 5 Attributes mapped to Nafath: Availability (24/7 SSO), Reliability (no false approvals), Safety (prevent identity misuse), Security (protect national ID DB), Resilience (survive peak load + DDoS).
  • Risks identified by source: Hardware (server saturation on salary day), Software (OTP/token-signer logic bugs), Operational (SDAIA misconfigurations).
  • Strategy: Dynamic Scaling, Microservices (independent OTP service), Diversity over pure Redundancy, NCA-aligned 2FA + signed JWTs, and read-only fallback for rapid recovery.
  • Trade-off ranking: Security > Reliability > Availability > Safety > Maintainability — because 100 % dependability is infinitely expensive.

🚀 The Capstone Project

Nusuk — Crowd Management & Permit Validation System

Domain: Safety-Critical Crowd Management (Hajj operations in Makkah)

Iteration: V1 group submission

Nusuk is a mission-critical permit-validation system that prevents catastrophic crowd-crushing during Hajj. Millions of pilgrims converge into confined spaces in Makkah; without strict capacity controls the risk of a crush is unacceptable. Nusuk performs precise permit validation that operates offline — so gatekeepers can always verify pilgrim credentials even when telecom networks fail.

Every design decision in this project is justified against one critical failure scenario: over-issuance of permits beyond physical zone capacity.

📊 Dependability Strategy (5 Attributes)

⏱

Availability

Zero-rated mobile routing keeps the pilgrim app reachable even under network throttling

🛡

Reliability

Near-zero POFOD on gate scanners via local SQLite caching instead of live 5G

⚕

Safety

ALARP-enforced hard-coded capacity limits — no admin override, even for VIPs

🔒

Security

RSA-2048 digitally signed offline permits + revocation lists prevent forgery

🔄

Resilience

The 4 R's: Recognition, Resistance, Recovery, Reinstatement — handle network drops gracefully

🏗 Architecture (V1)

Pattern: Client–Server with Edge (offline-capable) capabilities. Pilgrim Mobile App ↔ API Gateway ↔ Central Ministry Database, with Offline Scanners holding a Local Cache (SQLite) for verification when the network is down.

🔄 Software Reuse

RSA & AES standard cryptographic libraries (signed offline QR codes); SQLite + Realm for local caching, sync, and conflict resolution — avoiding costly and risky in-house crypto and storage.

🌐 Distributed Architecture

Edge nodes (gate scanners) operate autonomously on cached state; central Ministry DB is the master record reconciled via batched sync.

🧩 Component-Based

Independent components: Mobile App, API Gateway, Central DB, Offline Scanner, Local Cache — each replaceable without rewriting the whole system.

🛡 Hazard Analysis (Fault Tree)

Top event: Over-Issuance → Crowd Crush. Causes: (1) concurrency bug in dual-scanner counter, (2) state desynchronization caused by telecom congestion.

🔐 Cryptographic Validation

Each permit carries an RSA-2048 signature; scanners verify offline; central system can mark permits revoked and push updated lists at next sync.

⚖️ ALARP Enforcement

Capacity constants are hard-coded and non-overridable. No administrator can issue more permits than the physical safe limit.

📋 Project Evidence (V1)

  • Risk Metric: Near-zero POFOD on gate scanners; Availability via zero-rated routing
  • Architecture Pattern: Client–Server + Edge with offline-first local cache
  • Safety Standard: ALARP — hard-coded capacity limits, no override path
  • Critical Failure Scenario: Over-issuance of permits → crowd crush at gates

"Before HIMMA, I thought software engineering meant writing code. Now I understand it means building evidence — every design decision must be justifiable, traceable, and provable."

⚖️ Safety vs Reliability — My understanding

"A system can perfectly follow its specification and still cause harm. Safety is freedom from harm, Reliability is conformance to spec. A reliable weapon is still dangerous — that insight changed everything."

💼 What I will carry into my career

"The burden of proof is on the engineer. In safety engineering, you are guilty until proven innocent. I will never ship a critical system without a Safety Case — and I now know how to build one."
